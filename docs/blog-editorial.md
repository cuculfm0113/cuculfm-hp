# ブログ編集ルール（2026-08-20 文体リライト後）

並行作業: トップ / 3Dキャラ / `services/web` のポートフォリオ（床LP・犬図鑑）は別ライン。この文書の対象は `blog/`・`articles/`・サイトマップ・リダイレクト。`index.html`・`character-design/`・`services/dog/pet-floor/`・`services/dog/breeds/` は触らない。

## 文体ルール（現在公開している調査・清掃/犬関連13本に適用）

2026-08-20 に、Grok AIで下書きした定型的な文体を全面リライトした。以後この13本を書き直す・増やすときは次の型を守る。

- **型を作らない**: 「この記事でできるようになること / やらないこと」「結論」の見出し、「いまの仕事に印を付ける（コピペ）」の穴埋めテンプレ、「最終確認日: YYYY-MM-DD」のような事務的な言い回しは使わない。何を扱い何を扱わないかは導入の1〜2段落で会話的に伝え、要点は見出しなしで本文の流れに溶かし込む
- **語り口**: ククルFMの中の人（犬関連は for all dogs CUCUL）が自社の現場経験を交えて語る、落ち着いた です・ます調。誇張・営業トークはせず、経験と事実ベースで書く
- **出典の書き方**: 「〜が正」ではなく「判定の基準は発注者の仕様書と、日本下水道協会の維持管理指針に従います」のように自然な文で基準を示す
- **箇条書き・表**: 乱用しない。段落で語り、本当に比較が必要な表（方式の違い、道具、頻度など）だけ残す。実践的な手順や注意点で列挙が読みやすい場合は短いリストのままでよい
- **導入の変化**: 13本が同じ骨格に見えないよう、記事ごとに導入の入り方を変える
- 事実・数値・方式名・団体名・記事間の内部リンクは変更しない。新しい事実は創作しない
- 分量は元原稿の ±30% 程度に収める

古い「学習ゴール見出し」「コピペ穴埋め」の型は、現在非公開の AI学習・映像・Web 系の草稿（`blog/ai/`・`blog/ai-tools/`・`blog/video/`・`blog/web/`）にまだ残っている。これらを復活・公開する際は、上記の文体ルールでリライトしてから復活させる。

## 公開の合格線

- 読後に実際に使える内容がある（現場の判断軸、チェックリスト、比較表、禁止リスト）
- ツールの画面・料金は公式情報を基準にし、判断や基準の出典を本文中で自然に示す
- Unsplash の抽象AI画像は使わない。自社写真か表。なければヒーローなし
- `*-master` と `*-team-operations` は作らない
- 原稿は Markdown。公開HTMLは対象ファイルだけ生成する: `python3 scripts/build_blog.py blog/....md`
- 全件ビルド（`python3 scripts/build_blog.py --all`）は下書きの noindex を消すので使わない
- `scripts/cull_blog.py` はワンショット。再実行すると既存の301が消える

## 公開と下書き

- **公開**: 記事一覧に出す。sitemap に載せる
- **下書き（ディスクに残す）**: 書き直し待ち。sitemap に載せない。`<meta name="robots" content="noindex,follow">`（2026-08-19時点の下書きはなし）
- **廃止**: ファイル削除。`_redirects` で 301

URL対応は [blog-url-map.md](blog-url-map.md)。
