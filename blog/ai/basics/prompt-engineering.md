# プロンプトの型：目的・材料・形式・禁止・確認

**公開日**: 2026.08.18  
**カテゴリ**: AI  
**著者**: ククルFM編集部  
**概要**: 目的・材料・形式・禁止・確認の5ブロックで依頼し、2往復で使える下書きにする。

---

## この記事でできるようになること / やらないこと

- **できること**: 5ブロックの依頼文を書いて、2往復で使える下書きにする。
- **やらないこと**: 魔法の呪文、モデル名の暗記。画面操作は公式ヘルプを正とする。最終確認日: 2026-08-18

安全境界は [AI導入の始め方](./ai-introduction.html)。

## 結論

長い名文より、**抜けがない短い箇条書き**。最低5つ: 目的、読者、材料、出力形式、禁止。足りないときは「不明は不明と書く」を足す。

## 5ブロック（コピペ）

```
目的:
読者:
材料（固有名詞は伏せる）:
出力形式（見出し / 字数 / 表の列）:
禁止（推測しない、実名を作らない、URLを捏造しない）:
確認してほしいこと:
```

例（調査日報の要約）:

```
目的: 今日の現場メモを、明日の朝礼で読める短文にする
読者: 現場代理人と作業員
材料: 天候、作業内容（伏せ字）、未完了、明日の搬入
出力形式: 見出し3つ（完了 / 未完 / 明日）。全体400字以内
禁止: 住所と顧客名を書かない。ない数字を足さない
確認: 未完了が材料と一致しているか
```

## 2往復で仕上げる

1回目: 5ブロックをそのまま出す。80点で止める。  
2回目: 修正は1つだけ。「短い」「ですますに統一」「明日の搬入を先頭」など。

一度に10個直させると、直ったものと壊れたものが混ざる。

## 評価の仕方（3分）

出力を見て印を付ける。

- 材料にない事実が増えていないか
- 形式（字数・見出し）を守っているか
- 読者が次に動けるか

ダメならブロックを足す。モデルを変えるのはそのあと。

## 現場で使う短い型

**メール**: 件名候補3つ + 本文。相手、期限、お願いを材料に書く。  
**議事**: 決定 / ToDo（誰・いつ） / 未決。発言録の全文は渡さない。  
**チェック**: 「誤解されやすい箇所を先に列挙し、次に修正文」の順を指定する。

ChatGPT向けの業務例は [業務ワークフロー](../chatgpt/chatgpt-workflows-business.html)。
