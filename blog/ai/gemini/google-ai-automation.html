フォーム→シート：Geminiは要約と分類まで、送信は人

2026.08.19 ククルFM編集部

この記事でできるようになること / やらないこと

  • できること: 今日、問い合わせ用フォームの項目とシート列を1枚に書き、要約プロンプトを1回試す。
  • やらないこと: Gemini API、夜間バッチの本番、顧客への自動メール。フォームとシートの操作は Google フォーム と スプレッドシート が正。最終確認日: 2026-08-19

Workspaceの中の下書きは Gemini×Workspace。式とGASのテストは スプレッドシート×ChatGPT。

結論

自動化で先に壊れるのはAIではなく 項目の形。自由記述が多いと要約も分類も揺れる。返信を自動送信すると、誤分類がそのまま顧客に届く。最初の完成形は「人が30秒で判断できる表」まで。

設計（この順）

  1. フォーム: 選択肢を増やす。自由記述は「要点3行」1欄まで
  2. シート: 生データ列は触らない。右に要約 / 分類 / 人の確認
  3. 処理: 伏せ字の本文だけをGeminiに渡し、要約か分類の どちらか1つ
  4. 通知: 人が見てからメール。自動送信はしない

ステータスは「新規 / 対応中 / 保留 / 完了」の4つまで。

シート列（コピペ）

列中身誰が書く
Aタイムスタンプフォーム
B種別（選択肢）フォーム
C要点（3行）フォーム
D要約（200字）Geminiの下書き → 人
E分類（問い合わせ / 不具合 / 要望）Geminiの下書き → 人
F確認（OK / 修正）人だけ
G送信済み（空 / 日付）人だけ

実名と電話は、AIに渡す範囲から外す。渡すなら C 列だけ。

要約の依頼（コピペ）

入力は次の3行だけ。実名は無い前提。
出力: 200字以内。決定 / 未決 / 次アクション。
新しい事実を足さない。不明は不明。
分類は出さない（今日は要約だけ）。

最初の2週間は要約だけ。分類を足すのは、人が OK を付けた行が10件を超えてから。

やってはいけないこと

  • フォーム送信のたびに返信メールを自動で出す
  • 生データ列をAI出力で上書きする
  • ラベルを毎週増やす
  • 「緊急」をAIだけが決めて通知する

GASで時刻トリガーを足す日は、送信先を自分宛てにした版から。テストシート の段階と同じ。

演習

架空の問い合わせ5件をシートに手入力する。C列だけ渡して要約を埋める。F列を人が付ける。今日はメールを出さない。

チェックリスト
