Claude Artifacts：横の窓に出して、版を残す

2026.08.19 ククルFM編集部

この記事でできるようになること / やらないこと

  • できること: FAQか手順書の骨格を1つ、横の成果物として出させる。
  • やらないこと: 公開リンクの保証、プラン別機能の暗記。Artifactsの出し方・Publishの範囲は Anthropic ヘルプ（Artifacts） が正。最終確認日: 2026-08-19

前提は 始め方。長文の章立ては 分割と統合。

結論

同じ依頼を毎週打つなら、会話ログより 横に残る骨格 の方が再利用しやすい。ただし Publish するとリンクを知った人が見る場合がある。顧客の実名が入った成果物は公開しない。

用途1行（コピペ）

誰が: ＿＿ 何のために: ＿＿ 入力の必須: ＿＿ 出力の見出し: ＿＿ チェック: 誤解 / 漏れ / 禁止事項 公開してよいか: 社内のみ / リンク禁止

手順

  1. 禁止1行（実名と実額は入れない）
  2. 「次の見出しで成果物を出して。会話には要約だけ」と書く
  3. 見出し例: 用途 / 入力 / 出力 / やってはいけないこと / 確認
  4. サンプル1件で空欄とトーンを直す
  5. 版: v1.0 と日付を冒頭に書く
  6. Publish するかはヘルプを読んでから。迷ったら出さない

画面のタブ名や、モバイルにタブがあるかは変わる。無い日は通常のチャットで骨格を出して、人がファイルに保存してもよい。

やってはいけないこと

  • 顧客文面が入ったまま公開リンクを作る
  • テンプレを毎週増やして、どれが正か分からない
  • Artifacts を「アプリ開発の本番」だと思う（検証用の箱）
